# Frontend Design for Kane's Portfolio

Use this skill when creating or changing the personal website in this repository. The goal is a warm, authentic, plant-inspired portfolio that makes the work easy to explore and still communicates technical credibility to recruiters and collaborators.

## Before Making Changes

1. Read [design direction](./references/design-direction.md), [site structure and interactions](./references/site-structure.md), [project facts](./references/project-facts.md), and [content and accessibility guidance](./references/content-and-accessibility.md).
2. Inspect the existing pages, CSS, JavaScript, and assets before choosing an implementation. Preserve the static HTML/CSS/vanilla JavaScript approach unless the user asks to change it.
3. Keep the primary paths to projects, experience, and contact visible. Give MorningTide strong editorial prominence without hiding other work.
4. Separate completed projects from active research and work in progress. Do not invent public links, deployment status, clinical outcomes, or benchmark results.

## Design and Implementation

1. Use earth tones, restrained botanical references, generous editorial spacing, and purposeful imagery. Avoid generic gradients, dashboard density, excessive decoration, and motion that competes with the content.
2. Make core information reachable in a few clicks. Use clear page titles, descriptive links, and useful project summaries before deeper technical details.
3. Build interactions with semantic HTML and progressive enhancement. Keep filter controls keyboard accessible, expose their state, and provide visible feedback for actions such as copying an email address.
4. Make layouts responsive and usable with keyboard navigation, reduced-motion preferences, readable contrast, and meaningful image/video alternatives.
5. Reuse existing assets when appropriate. Do not add a resume download unless a real resume file is present and its path works.
6. Make precise, related changes and update these references when the user's preferences or confirmed project facts change.

## Verification

1. Check changed HTML for valid structure and working local links/media.
2. Check JavaScript syntax and confirm filters, media controls, navigation, and contact actions behave as described.
3. Review the responsive and reduced-motion styles; do not claim a visual/browser test that was not run.
